# 06.01 — CI workflow (`.github/workflows/ci.yml`)

**Owner:** the AWS account owner (infra/CI lead). **When:** milestone 2 (by
2026-11-09), right after the three project skeletons exist
(`03-backend-etl/01`, `04-frontend/01`, `05-infrastructure/01`).

CI is the single quality gate of the project (decision D15,
`01-foundation/05-testing-strategy.md`). It runs **every test** — backend,
frontend, end-to-end and infrastructure — and enforces the **85 % coverage**
gates. `deploy.yml` reuses this exact workflow as its `verify` job, so **a red
test blocks the merge (branch protection) and the deploy**.

## What it checks

| Job (status check name) | Folder | Checks |
|---|---|---|
| `Backend (Go)` | `backend/` | `gofmt` (fails on any unformatted file) → `go vet ./...` → `go test -race` with coverage of `./internal/...` and the **≥ 85 %** gate → `go build ./...` |
| `Frontend (React)` | `frontend/` | `npm ci` → `tsc --noEmit` → Biome lint/format check → Vitest unit + component tests with coverage thresholds **85 %** (lines, statements, functions, branches) → `vite build` |
| `End-to-end (Playwright)` | `frontend/` | `npm ci` → install Chromium + WebKit → `npm run test:e2e`: production build + `vite preview` serving the **golden snapshot** (`backend/testdata/golden/data`) at `/data`; projects `chromium` (Desktop Chrome) and `webkit` (iPhone 13); axe checks and no console errors in every spec |
| `Infrastructure (CDK)` | `infra/` | `npm ci` → `tsc --noEmit` → Biome lint/format check → assertion tests (`npm test`, coverage reported only) → `cdk synth` |

The four jobs are independent and run in parallel. The end-to-end job needs
no backend build: the golden snapshot is committed, and the backend's pipeline
test (job `Backend (Go)`) fails if the code no longer produces it — so a JSON
contract change shows up in both jobs of the same PR.

No AWS credentials are used anywhere in this workflow: the tests touch no
network (the backend uses an in-process fake upstream), and `cdk synth` needs
none because the account and region are pinned in `infra/lib/config.ts` and
the stack does no lookups. It is therefore safe on pull requests from forks.

## Triggers

| Trigger | Why |
|---|---|
| `pull_request` | The gate for merging into `main` (required checks). |
| `push` to any branch **except `main`** | Feedback on feature branches before a PR exists. `main` is excluded because `deploy.yml` runs on every push to `main` and calls this workflow first as its `verify` job; running it here as well would duplicate every check. Branch protection guarantees nothing reaches `main` without passing CI on its PR. |
| `workflow_dispatch` | Re-run manually. |
| `workflow_call` | Lets `deploy.yml` reuse these exact checks instead of restating them, so a red build or test can never reach CloudFront. |

## The file

```yaml
name: CI

on:
  pull_request:
  # Pushes to main are handled by deploy.yml, which calls this workflow before
  # publishing. Running here as well would duplicate every check.
  push:
    branches-ignore: [main]
  workflow_dispatch:
  # Lets deploy.yml reuse these exact checks rather than restating them.
  workflow_call:

# A newer push to the same ref supersedes the older run. github.workflow is the
# CALLER's name when this runs via workflow_call, so a deploy's verify job never
# cancels (or is cancelled by) a plain CI run on the same ref.
concurrency:
  group: ci-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read

defaults:
  run:
    shell: bash

jobs:
  backend:
    name: Backend (Go)
    runs-on: ubuntu-latest
    timeout-minutes: 15
    defaults:
      run:
        working-directory: backend
    steps:
      - uses: actions/checkout@v5

      - uses: actions/setup-go@v5
        with:
          go-version-file: backend/go.mod
          cache-dependency-path: backend/go.sum

      - name: Check formatting (gofmt)
        run: |
          unformatted="$(gofmt -l .)"
          if [ -n "$unformatted" ]; then
            echo "::error::These files are not gofmt-formatted (run 'gofmt -w .' in backend/):"
            echo "$unformatted"
            exit 1
          fi

      - name: go vet
        run: go vet ./...

      # Test-only code must never leak into the production binary
      # (03-backend-etl/09-integration-tests.md).
      - name: Guard — go-cmp and testsrv only in _test.go files
        run: |
          leaks="$(grep -rlE '"github.com/google/go-cmp|/internal/testsrv"' --include='*.go' . | grep -v '_test\.go$' | grep -v '^./internal/testsrv/' || true)"
          if [ -n "$leaks" ]; then
            echo "::error::Test-only imports found in production files:"
            echo "$leaks"
            exit 1
          fi

      - name: shellcheck the publish script
        run: shellcheck scripts/publish-data.sh   # preinstalled on ubuntu-latest

      # Unit tests, the fake-upstream integration test of the whole pipeline and
      # the golden-snapshot comparison. -race needs cgo, which the Ubuntu runner
      # provides (gcc is preinstalled); the code under test stays pure Go.
      - name: go test (race detector, coverage of ./internal/...)
        run: go test -race -covermode=atomic -coverpkg=./internal/... -coverprofile=coverage.out ./...

      - name: Coverage gate (>= 85%)
        run: |
          go tool cover -func=coverage.out | tail -n 1 | tee -a "$GITHUB_STEP_SUMMARY"
          go tool cover -func=coverage.out | awk '/^total:/ { sub("%","",$3); if ($3+0 < 85) { print "coverage " $3 "% < 85%"; exit 1 } else print "coverage " $3 "%" }'

      - name: go build
        run: go build ./...

  frontend:
    name: Frontend (React)
    runs-on: ubuntu-latest
    timeout-minutes: 15
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@v5

      - uses: actions/setup-node@v5
        with:
          node-version-file: .nvmrc
          cache: npm
          cache-dependency-path: frontend/package-lock.json

      - run: npm ci

      # Vite does not type-check during build, so without this a type error
      # would build and deploy happily.
      - name: Typecheck
        run: npm run typecheck

      - name: Lint and format check (Biome)
        run: npm run lint

      # Thresholds (85% lines/statements/functions/branches) live in
      # vite.config.ts; Vitest exits non-zero when any is missed.
      - name: Unit and component tests with coverage
        run: npm run test:coverage

      - name: Build
        run: npm run build

  e2e:
    name: End-to-end (Playwright)
    runs-on: ubuntu-latest
    timeout-minutes: 25
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@v5

      - uses: actions/setup-node@v5
        with:
          node-version-file: .nvmrc
          cache: npm
          cache-dependency-path: frontend/package-lock.json

      - run: npm ci

      # The browsers (~300 MB for Chromium + WebKit) are cached apart from
      # node_modules and keyed by the lockfile, which pins @playwright/test.
      - name: Cache Playwright browsers
        id: playwright-cache
        uses: actions/cache@v4
        with:
          path: ~/.cache/ms-playwright
          key: playwright-${{ runner.os }}-${{ hashFiles('frontend/package-lock.json') }}

      - name: Install Chromium and WebKit (with system dependencies)
        if: steps.playwright-cache.outputs.cache-hit != 'true'
        run: npx playwright install --with-deps chromium webkit

      - name: Install system dependencies only (browsers restored from cache)
        if: steps.playwright-cache.outputs.cache-hit == 'true'
        run: npx playwright install-deps chromium webkit

      # playwright.config.ts builds the app, starts `vite preview` with
      # E2E_DATA_DIR=../backend/testdata/golden/data and runs both projects.
      - name: End-to-end tests (Chromium + WebKit, against the golden snapshot)
        run: npm run test:e2e

      - name: Upload the Playwright report on failure
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: |
            frontend/playwright-report/
            frontend/test-results/
          retention-days: 7

  infra:
    name: Infrastructure (CDK)
    runs-on: ubuntu-latest
    timeout-minutes: 10
    defaults:
      run:
        working-directory: infra
    steps:
      - uses: actions/checkout@v5

      - uses: actions/setup-node@v5
        with:
          node-version-file: .nvmrc
          cache: npm
          cache-dependency-path: infra/package-lock.json

      - run: npm ci

      - name: Typecheck
        run: npm run typecheck

      - name: Lint and format check (Biome)
        run: npm run lint

      # Security invariants: bucket, OAC, headers/CSP, OIDC trust, exact
      # permissions, imported provider, pinned account, SPA rewrite table.
      # Coverage is printed, not gated.
      - name: Assertion tests
        run: npm test

      # Catches a stack that no longer synthesises before a human tries to deploy it.
      - name: cdk synth
        run: npx cdk synth --quiet
```

## Scripts and commands this relies on

| Folder | Script / command | Defined in |
|---|---|---|
| `backend/` | `go test -race -covermode=atomic -coverpkg=./internal/... -coverprofile=coverage.out ./...` + the awk gate | `01-foundation/05-testing-strategy.md` (same as `make test-backend`) |
| `frontend/` | `typecheck`, `lint`, `test:coverage`, `build`, `test:e2e` | `04-frontend/01-project-setup.md`, `04-frontend/08-testing.md` |
| `frontend/` | `playwright.config.ts` (projects `chromium` + `webkit`, `webServer` on the golden snapshot) | `04-frontend/01-project-setup.md` Step 3b |
| `infra/` | `typecheck`, `lint`, `test` | `05-infrastructure/01-cdk-stack.md` Steps 1 and 6b |

If a script or the coverage command changes there, change it here in the same PR.

## Running the same checks locally

```bash
make check     # format, vet, lint, typecheck, all tests, build, cdk synth
make test      # only the four test suites
```

See `01-foundation/02-repository-layout.md` (Makefile) and
`01-foundation/05-testing-strategy.md` (first-time Playwright browser install).

## Step by step

1. Create `.github/workflows/ci.yml` with the content above on a branch
   `ci/add-ci`. Each project skeleton already ships with at least one test
   (a skeleton without tests fails the coverage gates by design).
2. Push the branch: the `push` trigger runs it. All four jobs must be green.
3. Open the PR: the `pull_request` trigger runs it again.
4. Ask the repository admin to add the **four** check names to the `main`
   ruleset (`05-infrastructure/02-github-oidc-and-variables.md`), then merge.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `coverage 8x.x% < 85%` | New code without tests | Add the tests in the same PR. Lowering the gate is a decision (edit D15), never a silent change here. |
| Golden snapshot diff in `Backend (Go)` | The pipeline output changed | If intended, regenerate with `go test ./internal/pipeline -run TestPipeline -update`, commit the new golden files; the e2e job then runs against them. |
| `End-to-end (Playwright)` fails only in WebKit | Safari-specific CSS/JS behaviour | Download the `playwright-report` artifact, open the trace (`npx playwright show-trace`). |
| `End-to-end` fails with "no data" everywhere | `backend/testdata/golden/data` missing or not committed | Run the backend pipeline test with `-update` and commit the folder. |
| `Infrastructure (CDK)` assertion fails after a CDK upgrade | An internal template detail changed | Fix the expectation in the upgrade PR; never loosen it to "any value". |
| `go test -race` fails with a cgo error locally | No C compiler on the machine | Install the platform's build tools (Xcode CLT on macOS, `build-essential` on Debian/Ubuntu). |

## Done when

- [ ] A PR shows four green checks: `Backend (Go)`, `Frontend (React)`,
      `End-to-end (Playwright)`, `Infrastructure (CDK)`.
- [ ] The `Backend (Go)` job summary shows the total coverage (≥ 85 %).
- [ ] On a scratch branch, deleting one test so coverage drops below 85 % makes
      the job fail (then delete the branch).
- [ ] The four checks are required on `main`.
