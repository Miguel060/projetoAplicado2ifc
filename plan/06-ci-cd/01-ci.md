# 06.01 — CI workflow (`.github/workflows/ci.yml`)

**Owner:** the AWS account owner (infra/CI lead). **When:** milestone 2 (by 2026-11-09), right after the three
project skeletons exist (`03-backend-etl/01`, `04-frontend/01`, `05-infrastructure/01`).

## What it checks (and what it deliberately does not)

| Job (status check name) | Folder | Checks |
|---|---|---|
| `Backend (Go)` | `backend/` | `gofmt` (fails on any unformatted file), `go vet ./...`, `go build ./...` |
| `Frontend (React)` | `frontend/` | `npm ci`, Biome lint/format check, `tsc --noEmit`, `vite build` |
| `Infrastructure (CDK)` | `infra/` | `npm ci`, Biome lint/format check, `tsc --noEmit`, `cdk synth` |

**No test step.** The project ships production code only (decision D11); the
quality gates are compilers, type checkers, linters, the ETL's own runtime
validation (`03-backend-etl/08-validate-and-publish.md`) and the manual
launch checklist (`07-delivery/02-launch-checklist.md`).

No AWS credentials are used here: `cdk synth` needs none because the account
and region are pinned in `infra/bin/app.ts` and the stack does no lookups.

## Triggers

| Trigger | Why |
|---|---|
| `pull_request` | The gate for merging into `main` (required checks). |
| `push` to any branch **except `main`** | Feedback on feature branches before a PR exists. `main` is excluded because `deploy.yml` runs on every push to `main` and calls this workflow first as its `verify` job; running it here as well would duplicate every check. Branch protection guarantees nothing reaches `main` without passing CI on its PR. |
| `workflow_dispatch` | Re-run manually. |
| `workflow_call` | Lets `deploy.yml` reuse these exact checks instead of restating them, so a red build can never reach CloudFront. |

## The file

```yaml
name: CI

on:
  pull_request:
  # Pushes to main are handled by deploy.yml, which calls this workflow before
  # publishing. Running here as well would duplicate every check.
  push:
    branches-ignore: [main]
  workflow_dispatch:
  # Lets deploy.yml reuse these exact checks rather than restating them.
  workflow_call:

# A newer push to the same ref supersedes the older run. github.workflow is the
# CALLER's name when this runs via workflow_call, so a deploy's verify job never
# cancels (or is cancelled by) a plain CI run on the same ref.
concurrency:
  group: ci-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read

defaults:
  run:
    shell: bash

jobs:
  backend:
    name: Backend (Go)
    runs-on: ubuntu-latest
    timeout-minutes: 10
    defaults:
      run:
        working-directory: backend
    steps:
      - uses: actions/checkout@v5

      - uses: actions/setup-go@v5
        with:
          go-version-file: backend/go.mod
          cache-dependency-path: backend/go.sum

      - name: Check formatting (gofmt)
        run: |
          unformatted="$(gofmt -l .)"
          if [ -n "$unformatted" ]; then
            echo "::error::These files are not gofmt-formatted (run 'gofmt -w .' in backend/):"
            echo "$unformatted"
            exit 1
          fi

      - name: go vet
        run: go vet ./...

      - name: go build
        run: go build ./...

  frontend:
    name: Frontend (React)
    runs-on: ubuntu-latest
    timeout-minutes: 10
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@v5

      - uses: actions/setup-node@v5
        with:
          node-version-file: .nvmrc
          cache: npm
          cache-dependency-path: frontend/package-lock.json

      - run: npm ci

      - name: Lint and format check (Biome)
        run: npm run lint

      # Vite does not type-check during build, so without this a type error
      # would build and deploy happily.
      - name: Typecheck
        run: npm run typecheck

      - name: Build
        run: npm run build

  infra:
    name: Infrastructure (CDK)
    runs-on: ubuntu-latest
    timeout-minutes: 10
    defaults:
      run:
        working-directory: infra
    steps:
      - uses: actions/checkout@v5

      - uses: actions/setup-node@v5
        with:
          node-version-file: .nvmrc
          cache: npm
          cache-dependency-path: infra/package-lock.json

      - run: npm ci

      - name: Lint and format check (Biome)
        run: npm run lint

      - name: Typecheck
        run: npm run typecheck

      # Catches a broken stack before a human tries to deploy it.
      - name: cdk synth
        run: npx cdk synth --quiet
```

## Scripts this relies on

| Folder | `package.json` script | Defined in |
|---|---|---|
| `frontend/` | `lint` (`biome check .`), `typecheck` (`tsc --noEmit`), `build` (`vite build`) | `04-frontend/01-project-setup.md` |
| `infra/` | `lint`, `typecheck` | `05-infrastructure/01-cdk-stack.md` Step 1 |

If a script is renamed there, rename it here in the same PR.

## Running the same checks locally

```bash
make check     # see 01-foundation/02-repository-layout.md
```

## Step by step

1. Create `.github/workflows/ci.yml` with the content above on a branch
   `ci/add-ci`.
2. Push the branch: the `push` trigger runs it. All three jobs must be green.
3. Open the PR: the `pull_request` trigger runs it again.
4. Ask the repository admin to add the three check names to the `main` ruleset
   (`05-infrastructure/02-github-oidc-and-variables.md`), then merge.

## Done when

- [ ] A PR shows three green checks: `Backend (Go)`, `Frontend (React)`, `Infrastructure (CDK)`.
- [ ] A deliberately unformatted Go file on a scratch branch makes `Backend (Go)` fail (then delete the branch).
- [ ] The three checks are required on `main`.
