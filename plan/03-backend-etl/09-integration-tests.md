# 03.09 — Fake upstream, synthetic fixtures, pipeline integration test, golden snapshot

## Goal

Prove the **whole** ETL — download → parse → select → enrich → SQLite →
JSON → validate — end to end, with **no network**, deterministically, on
every pull request and before every data refresh. Its output, committed as
the **golden snapshot**, is also the frontend's end-to-end fixture, which
makes it the contract test between backend and frontend
(`01-foundation/05-testing-strategy.md`, decision D15).

Built alongside steps 02–08: start the fixture set and `testsrv` together
with step 02, add each source's fixture files in the step that loads them,
and switch on the golden comparison once step 07 exports JSON.

`testsrv` is a normal (non-`_test`) package so other packages' tests can
import it, but **only `*_test.go` files import it** (CI check:
`grep -rln "internal/testsrv" backend --include=*.go | grep -v _test.go`
must print nothing). It sits under `./internal/...`, so it counts toward —
and is covered by — the 85 % gate.

## 1. The fake upstream — `internal/testsrv`

### 1.1 Shape

```go
package testsrv

// FixtureTime is the only time that appears in the fixtures and the golden
// snapshot: zip member mtimes, Last-Modified headers and the injected clock.
var FixtureTime = time.Date(2099, 1, 1, 0, 0, 0, 0, time.UTC)

type Server struct {
	URL  string       // http://127.0.0.1:<port>
	root string       // backend/testdata/sources (found relative to this file via runtime.Caller)
	// …
}

func New(t testing.TB) *Server       // starts httptest.Server; t.Cleanup closes it
func (s *Server) URLs() config.URLs  // every base URL pointing at s.URL (for unit tests)
func (s *Server) Transport() http.RoundTripper // real upstream hosts → this server (for the integration test)
func (s *Server) Requests() []Request          // log: Method, Path, RawQuery, Range, UserAgent, Status
func (s *Server) Now() time.Time               // returns FixtureTime (handy as Options.Now)
```

### 1.2 Routes (paths mirror the fixture tree)

| Path on the fake server | Served from | Notes |
|---|---|---|
| `/tse/odsele/<dir>/<name>.zip` | `sources/tse/odsele/<dir>/<name>.zip/` (a **directory**) | zip built in memory from the directory's files (§1.3) |
| `/tse/fotos/foto_cand2026_SC_div.zip` | `sources/tse/fotos/foto_cand2026_SC_div.zip/` | idem |
| `/camara/api/v2/deputados` | `sources/camara/api/v2/deputados.json` | answers **400** unless `idLegislatura=57&siglaUf=SC` |
| `/camara/api/v2/deputados/{id}` | `sources/camara/api/v2/deputados/{id}.json` | 404 if absent |
| `/camara/api/v2/proposicoes` | `sources/camara/api/v2/proposicoes/{idDeputadoAutor}.json` (array of items) | §1.4 |
| `/camara/arquivos/...` | `sources/camara/arquivos/...` | plain files |
| `/camara/cotas/Ano-YYYY.csv.zip` | `sources/camara/cotas/Ano-YYYY.csv.zip/` | zip built in memory |
| `/cgu/EmendasParlamentares.zip` | `sources/cgu/EmendasParlamentares.zip/` | zip with all three members |
| `/cgu/UNICO` | — | `302` → `/cgu/EmendasParlamentares.zip` (like the real `/UNICO` redirect) |
| anything else | — | 404 |

Every file and zip is served with `http.ServeContent(w, r, name,
FixtureTime, bytes.NewReader(b))`, which gives **real `Range` support**
(`206`, `Content-Range`, `Accept-Ranges: bytes`), `HEAD`, and a stable
`Last-Modified` — so the remote-zip reader (step 02) is exercised exactly as
against the real CDNs.

### 1.3 Zips built in memory

At `New`, every fixture directory whose name ends in `.zip` becomes one zip:

- members = the directory's files, **sorted by name**, method Deflate,
  `Modified = FixtureTime` → byte-identical zips on every run;
- a file named `.padding` (content: a byte count, e.g. `2097152`) is not a
  member: it adds a **stored** member `PADDING.bin` of that many zero bytes
  **before** the real members, so tests can assert that a range read
  transferred far less than the zip size (the votes zip uses 2 MiB).

Fixture bytes are never transcoded: Latin-1 stays Latin-1, CRLF stays CRLF.

### 1.4 The Câmara API handler

`/proposicoes` reproduces the behaviour verified on the real API
(`02-data-sources/02-camara.md`):

1. requires `idDeputadoAutor`, `siglaTipo`, `dataApresentacaoInicio`
   (else **400** — this is how tests prove our query string);
2. filters the deputy's items by `siglaTipo` (comma list) and
   `dataApresentacao >= dataApresentacaoInicio`;
3. sorts by `id` desc (`ordem=DESC&ordenarPor=id`);
4. page size = `min(itens, 2)` — the cap of 2 forces pagination on 5 bills;
5. responds `{"dados": [...], "links": [self, next?, first, last]}` with
   header `X-Total-Count`. Link `href`s use the **host the client asked
   for**: through `Transport()` they are `https://dadosabertos.camara.leg.br/api/v2/proposicoes?…&pagina=N`,
   so following `next` goes through the transport again.

### 1.5 `Transport()` — real URLs, fake upstream

The integration test keeps `URLs = config.DefaultURLs()` so the golden
snapshot records the **real** `fileUrl`s (stable, `https://`, and accepted by
validation check 6). It injects `Options.HTTP.Transport = srv.Transport()`,
a `RoundTripper` that rewrites:

| Real prefix | Fake path |
|---|---|
| `https://cdn.tse.jus.br/estatistica/sead/odsele/` | `/tse/odsele/` |
| `https://cdn.tse.jus.br/estatistica/sead/eleicoes/eleicoes2026/fotos/` | `/tse/fotos/` |
| `https://dadosabertos.camara.leg.br/api/v2/` | `/camara/api/v2/` |
| `https://dadosabertos.camara.leg.br/arquivos/` | `/camara/arquivos/` |
| `https://www.camara.leg.br/cotas/` | `/camara/cotas/` |
| `https://dadosabertos-download.cgu.gov.br/PortalDaTransparencia/saida/emendas-parlamentares/` | `/cgu/` |
| `https://portaldatransparencia.gov.br/download-de-dados/emendas-parlamentares/UNICO` | `/cgu/UNICO` |

Any other URL fails with `network disabled in tests: <url>`. That is the
mechanical guarantee that **no test touches the network**.

### 1.6 Failure injection (`inject.go`)

| Method | Effect |
|---|---|
| `FailNext(path string, statuses ...int)` | the next `len(statuses)` requests to `path` answer those codes (e.g. `504, 504` or `429` with `Retry-After: 1`) |
| `IgnoreRange(path string)` | always `200` with the full body, no `Accept-Ranges` — triggers the full-download fallback |
| `Delay(path string, d time.Duration)` | sleeps before answering (timeouts, context cancellation) |
| `Remove(path string)` | path answers 404 (e.g. the direct CGU zip, to exercise `/UNICO`) |
| `Replace(path string, b []byte)` | serve these bytes instead of the fixture (for a file) or as an extra/replacing member (for `zipPath + "/" + member`) — schema drift, odd rows |
| `ShiftPages(deputyID int)` | repeats the last item of page 1 at the top of page 2 (pagination drift) |
| `Requests()` / `ResetLog()` | request log for assertions (cache hits, Range use, User-Agent, query strings) |

## 2. The synthetic fixture set — `backend/testdata/sources/`

### 2.1 Rules

- **Synthetic only.** No row comes from a real file. Names are
  `… TESTE …`, parties `PTX`/`PTY`/`PTZ`, federation `FTX`, ballot numbers
  `99xx` (federal) and `99xxx` (state), `SQ_CANDIDATO` `9900000000xx`,
  Câmara ids `9900xx`, municipality `OUTRA CIDADE TESTE` (code `99999`).
  The only real identifiers are the ones the code **must** recognise:
  `VIDEIRA`, TSE code `83798`, IBGE `4219309`, UF `SC`, election `6259` /
  `04/10/2026`, office codes, column names.
- **Fake CPFs** are repeated digits or obvious patterns (`11111111111`,
  `22222222222`, `12121212121`…) — invalid by the CPF check-digit rule —
  and are **shared** between TSE and Câmara fixtures so the CPF join is
  exercised.
- **Planted strings** that must never reach the output (asserted in §3):
  donor `DOADOR FICTICIO TESTE`, natural persons `PESSOA FISICA TESTE UM` /
  `DOIS`, documents `99999999999` / `88888888888`, e-mail column value
  `EMAIL_FICTICIO_TESTE`, voter id `999988887777`, and every CPF.
- **Real layouts and encodings**: all real columns in the real order (even
  those we ignore), TSE files **Latin-1 + CRLF**, CGU **Windows-1252**, Câmara
  bulk **UTF-8 with BOM**, decimals as the source writes them. Generation
  stamps `DT_GERACAO = 01/01/2099`, `HH_GERACAO = 00:00:00`.
- **Editing**: write the CSV in UTF-8, then convert —
  `iconv -f UTF-8 -t ISO-8859-1` (TSE) or `-t WINDOWS-1252` (CGU) — and
  `unix2dos` for TSE. `.gitattributes` (`backend/testdata/** -text`) keeps
  Git from touching the bytes. `testsrv/fixtures_test.go` fails if a TSE or
  CGU file is valid UTF-8 while containing non-ASCII text (a sign an editor
  re-saved it), if a Câmara bulk file lacks its BOM, or if any planted
  string appears in `golden/`.

### 3.2 `TestPipeline` — the golden snapshot

```go
var update = flag.Bool("update", false, "rewrite backend/testdata/golden/data from this run")

func TestPipeline(t *testing.T) {
	srv := testsrv.New(t)
	out := t.TempDir()
	res, err := pipeline.Run(context.Background(), goldenOptions(t, srv, out))
	if err != nil {
		t.Fatal(err)
	}
	if res.Version != "20990101T000000Z" { t.Fatalf("version %s", res.Version) }

	const golden = "../../testdata/golden/data"
	if *update {
		replaceDir(t, out, golden) // rm -rf golden; copy out → golden
		t.Log("golden snapshot rewritten — review the diff before committing")
		return
	}
	compareTrees(t, out, golden)
}
```

`compareTrees` (in `golden_test.go`):

1. **Same file list** (missing / extra files are reported by name).
2. `*.json`: decoded to `any` and compared with `cmp.Diff`, so the failure
   shows the exact path that changed. One documented exception:
   `index.json` → `dataset.sha256` and `dataset.bytes` are ignored, because
   SQLite file bytes can change with a driver upgrade without any data
   change.
3. `dataset.sqlite`: compared **logically** — every table dumped as
   `SELECT * FROM <t> ORDER BY <primary key>` to text, then `cmp.Diff`.
4. Everything else (photos, `latest.json`): byte-exact.

Regenerate deliberately:

```bash
cd backend && go test ./internal/pipeline -run TestPipeline -update
git diff --stat testdata/golden    # review: every change must be explained in the PR
```

## 5. How the frontend consumes it

The frontend's end-to-end suite (`04-frontend/08-testing.md`) serves this
folder at `/data` through the Vite preview middleware
(`E2E_DATA_DIR=../backend/testdata/golden/data`), and `e2e/golden.ts` reads
the same files from disk to pick candidates **by property, never by slug**.
Consequences for backend changes:

- A JSON shape change regenerates the golden snapshot in the same PR, and the
  e2e job runs against it in that PR → contract breaks fail CI before
  merging.
- Removing a fixture candidate that covers a requirement in the §4 table
  breaks `findCandidate(...)` in the frontend suite with a message pointing
  back here — extend the fixtures instead.
- The validation tests of step 08 also start from this snapshot.

## 6. Shared text-normalisation vectors

`testdata/textnorm-vectors.json` (repository root) is an array of

## Pitfalls

- Editing a fixture in an editor that "helpfully" saves UTF-8 or LF: the
  fixture guard test fails; re-convert with `iconv`/`unix2dos`.
- Running `-update` to "make the test pass" without reading the diff — the
  behaviour assertions in §3.3 exist to catch exactly that.
- Real data in fixtures, even "just one row to reproduce a bug": forbidden.
  Reproduce the shape with invented values.
- Time-dependent code that bypasses `Options.Now` shows up as a golden diff
  on the next day — fix the code, not the golden.
