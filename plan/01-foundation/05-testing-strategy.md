# 05 — Testing strategy (the contract every step follows)

Decided 2026-10-21 (D15). Every step that adds code adds its tests **in the
same pull request**, and nothing deploys unless all tests pass and coverage
holds.

## The gates

| Gate | Where it runs | Blocks |
|---|---|---|
| Backend unit + integration tests, `-race`, **coverage ≥ 85 %** of `./internal/...` | `ci.yml` → job `backend` | merge (branch protection) and every site deploy (`deploy.yml` reuses `ci.yml`) |
| Same backend tests | `refresh-data.yml`, before the ETL runs | publishing a data snapshot |
| Frontend unit + component tests, **coverage ≥ 85 %** (lines, statements, functions, branches) of `src/` | `ci.yml` → job `frontend` | merge and deploy |
| Frontend end-to-end tests, **Chromium (desktop) + WebKit (iPhone 13)**, with automated accessibility checks | `ci.yml` → job `e2e` | merge and deploy |
| Infrastructure assertion tests (security invariants) | `ci.yml` → job `infra` | merge and deploy |
| Interactive browser check of every frontend step (Claude in Chrome) | developer, before opening the PR | opening the PR |

Coverage exclusions (and only these): Go `cmd/` (a thin `main`), frontend
`src/components/ui/**` (generated by shadcn), `src/main.tsx`, `**/*.d.ts`,
test files themselves.

## Test data: synthetic only

The repository is public and the real files contain personal data (D10).
Therefore **no row is ever copied from a real source file**.

- Fixtures use the **real column layouts, encodings and quirks** (Latin-1 /
  Windows-1252, `;`, BOM, `1.234,56`, `#NULO#`, `-3`…) with invented values:
  names like `CANDIDATA TESTE UM`, party `PTX`, numbers `9901`, etc.
- CPFs in fixtures are obviously fake and invalid (`11111111111`,
  `22222222222`, …), shared between the TSE and Câmara fixtures so the CPF
  join can be tested.
- Fixture files under `backend/testdata/**` are byte-exact: `.gitattributes`
  marks them `-text` so Git never converts encodings or line endings.

## Backend (Go)

| Kind | What | How |
|---|---|---|
| Unit | parsers, value conversion, sentinels, text normalisation, ranking/selection, author matching, export mapping, slug rule, validation gates, retry policy | stdlib `testing`, table-driven; `github.com/google/go-cmp` (test-only) for readable diffs |
| Fake upstream | one in-process HTTP server that serves every source from `backend/testdata/sources/`: zips are **built in memory** at start-up from the fixture CSVs; `http.ServeContent` gives real `Range` support (so the remote-zip reader is exercised); handlers can inject `500`, `504`, slow responses and `429` | package `internal/testsrv` (test helper, imported only by `_test.go` files) |
| Integration | the **whole pipeline** — download → parse → select → enrich → SQLite → JSON → validate — against the fake upstream, with an injected clock | `internal/pipeline.Run(ctx, Options)` called from `internal/pipeline/pipeline_test.go` |
| Golden snapshot | the integration test compares its JSON output with `backend/testdata/golden/data/` and fails on any difference; regenerate deliberately with `go test ./internal/pipeline -run TestPipeline -update` | the same golden snapshot is the frontend's end-to-end fixture (below) |

The integration test requires a small refactor already reflected in the
plan: the orchestration lives in `internal/pipeline` (`Run(ctx, Options)
(Result, error)`), and `cmd/ingest` only turns flags into `Options`. Every
source URL is an `Options` field defaulting to the real one, so tests point
them at the fake server. **No test touches the network.**

Command (CI and `make test-backend`):

```bash
cd backend
go test -race -covermode=atomic -coverpkg=./internal/... -coverprofile=coverage.out ./...
go tool cover -func=coverage.out | awk '/^total:/ { sub("%","",$3); if ($3+0 < 85) { print "coverage " $3 "% < 85%"; exit 1 } else print "coverage " $3 "%" }'
```

## The golden snapshot is the contract test

```
backend/testdata/sources/   ──(fake upstream)──►  pipeline.Run  ──►  backend/testdata/golden/data/
                                                                          │  latest.json, <version>/index.json,
                                                                          │  candidates/*.json, photos/*.jpg, dataset.sqlite
                                                                          ▼
                                       frontend e2e serves it at /data  ──►  Playwright specs
```

If the backend changes the JSON shape, the golden snapshot changes in the
same PR, and the frontend end-to-end tests run against it in that PR. A
contract break therefore fails CI before it can reach production. The golden
snapshot uses a fixed version string (`20990101T000000Z`) so it never looks
like real data.

## Frontend (TypeScript)

| Kind | Tools (pinned) | What |
|---|---|---|
| Unit | Vitest 5.0.5, `@vitest/coverage-v8` 5.0.5 | formatters, text normalisation, search/filter/sort, URL params, safe URLs, fetchers and loaders (mocked `fetch`), error mapping |
| Component | Testing Library: `@testing-library/react` 16.3.3, `@testing-library/dom` 10.4.2, `@testing-library/user-event` 14.6.8, `@testing-library/jest-dom` 7.0.1; `jsdom` 30.1.3 | each page rendered with `createMemoryRouter` and fixture data: sections in order, empty states, source notes, filters reacting to input, links |
| End-to-end | `@playwright/test` 1.64.1, `@axe-core/playwright` 4.14.0 | against the **production build** (`vite build` + `vite preview`) with `/data` served from the golden snapshot; projects `chromium` (Desktop Chrome) and `webkit` (iPhone 13) |

End-to-end must cover, per route: it loads, its key interactions work,
keyboard navigation reaches every control, **zero axe violations** for the
`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` tags, and **no console errors**.
Plus two failure scenarios: no data yet (`/data/latest.json` → 404: landing
shows "Dados em preparação", other routes show the documented message) and
schema mismatch.

Shared test vectors: `testdata/textnorm-vectors.json` at the repository root
holds input → expected pairs for text normalisation. Both the Go and the
TypeScript test suites read it, so the two implementations cannot drift.

## Infrastructure (CDK)

Vitest + `aws-cdk-lib/assertions` in `infra/test/`. Coverage is reported, not
gated (the code is declarative; the assertions are what matter). Required
assertions:

- bucket: Block Public Access fully on, SSL enforced, `RETAIN`;
- distribution: Origin Access Control, redirect to HTTPS, viewer-request
  function attached, response-headers policy with the exact CSP string;
- deploy role: trust has `aud = sts.amazonaws.com` and **exactly** the two
  subjects, no wildcard; permissions are exactly the documented set;
- the OIDC provider is **imported** — the template contains no OIDC provider
  resource;
- the stack is pinned to account `436812234154` / `us-east-1`;
- the CloudFront Function source (`lib/spa-rewrite.js`) is evaluated in a
  `vm` context and its rewrite table is tested (`/`, `/candidatos`,
  `/candidatos/a-b-123`, `/sobre` → `/index.html`; `/data/latest.json`,
  `/assets/x.js` unchanged).

## Interactive browser check of every frontend step

Automated tests prove what we thought of. The interactive check catches what
we did not. **Before opening the PR of any step that changes the frontend:**

1. Build and serve locally: `npm run build && npm run preview` (with a local
   snapshot from `make ingest`, or the golden snapshot).
2. With **Claude in Chrome** (`mcp__claude-in-chrome__*` tools; load them
   first), in a new tab:
   - exercise **every control added or changed** in the step and confirm its
     visible result;
   - keyboard-only pass: Tab order, visible focus, Enter/Space/Escape;
   - resize to **360 px** wide and to desktop width; no horizontal scroll;
   - read console messages: **zero errors**; read network requests: no
     unexpected 4xx/5xx;
   - record a short GIF of the main flow (`gif_creator`) with a meaningful
     name (e.g. `step-19-search.gif`) and mention it in the PR description.
3. If Claude in Chrome is not connected, or a check needs scripting
   (e.g. throttled network, many repetitions), use **Playwright** instead —
   the Playwright MCP server or a throw-away script — and say so in the PR.
4. Anything that fails is fixed in the same step. Anything worth keeping as a
   regression check becomes a Playwright spec in the same PR.

## Local commands (Makefile)

| Target | Runs |
|---|---|
| `make test-backend` | Go tests with race detector and the 85 % gate |
| `make test-frontend` | Vitest with coverage thresholds |
| `make test-e2e` | build + Playwright (Chromium + WebKit) against the golden snapshot |
| `make test-infra` | infra assertion tests |
| `make test` | all four |
| `make check` | format, vet, lint, typecheck, `make test`, build, `cdk synth` — exactly what CI runs |

First-time setup for end-to-end tests: `cd frontend && npx playwright install --with-deps chromium webkit`.
